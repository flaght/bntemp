# 08 Option Vega 分钟日志字段说明

更新：2026-10-15（Asia/Shanghai）。适用于当前 `OptionSessionRunner`、`OptionVegaStrategy` 和 `minute_diagnostics.py` 的日志实现。本文解释现有代码，不改变策略规则或运行参数。

## 1. 这三条日志说明了什么

以2026-10-15的11:19样例为例：该分钟必需的指数、持仓期权、同月期货均在接收期限内到达；程序在11:19:20.760封帧并执行判断。策略仍持有 `MO2611-C-7400` 空1手，不满足常规退出条件；尚未到13:36选约时点，此分钟也未触发期货对冲重算，因此没有提交新目标。11:20心跳表明程序继续轮询，最后封闭分钟为11:19。

这三类记录是不同层次的观测：

| 日志 | 产生位置与频率 | 可以回答的问题 |
| --- | --- | --- |
| 分钟行情汇总 | 等待期限到达，分钟缓冲封帧后，每帧一次 | 本分钟有哪些输入、必需腿是否齐全、什么时候收到 |
| 分钟决策汇总 | 策略处理封闭帧后；缺指数跳过、异常也有对应记录 | 本策略仓位、退出检查、选约及对冲分支、是否提交目标 |
| 分钟运行心跳 | `poll_live_inputs()` 中，接收门开启时，每个墙钟自然分钟首次轮询输出 | 轮询是否仍在推进、最后封帧位置、有无待封帧和已记录失败 |

心跳由同一控制流程触发，不是独立监控线程。控制流程阻塞时心跳也可能推迟；它不保证严格每60秒输出。单条心跳不能证明全部行情、账户和网络都正常。

## 2. 时间、单位和数量约定

- JSON中的时间显式带 `+08:00`，为北京时间。样例行首 `03:19:20` 与JSON内 `11:19:20+08:00` 相差8小时，符合日志格式器使用UTC的情况；行首时区由部署环境决定，不能把它们当成8小时行情延迟。
- `minute` 是归一化后的分钟估值/收盘边界。若源标签为 `end`，11:19通常对应截至11:19的已结束分钟；若源标签为 `start`，适配层先加一分钟。不能把11:19帧当成11:19至11:20尚未结束的行情。
- 价格是源Bar的收盘价格，不是最新买卖盘口，也不是现金金额或成交保证。期权价格46是报价点数；合约乘数及费用另算。
- 仓位、目标和在途量以手表示，正为多、负为空。Decimal数量序列化成字符串，例如 `"-1"`；价格缓存使用浮点数。
- `*_total` 一般是当前对象的累计数，不是本分钟新增数；具体恢复及重置范围见第6节。

## 3. 分钟行情汇总

### 3.1 顶层字段

| 字段 | 当前实现的含义 | 本次样例解释 |
| --- | --- | --- |
| `strategy_id` | 策略身份，用于对应归属仓位和日志 | `option-vega-live` |
| `minute` | 本帧归一化后的业务估值分钟 | `11:19:00+08:00` |
| `deadline` | 本帧第一条被接纳的观测接收时间，加配置宽限期；不是固定的整分钟加20秒 | `11:19:20.549111` |
| `sealed_at` | 控制线程调用封帧时的墙钟，也是该帧的请求时间 | `11:19:20.760277` |
| `status` | 按封帧时动态必需集合判断：全部在本帧则 `COMPLETE`，否则 `INCOMPLETE` | 必需集合齐全 |
| `missing_required` | 必需集合中未进入本帧的键，按键排序 | `[]`，无必需腿缺失 |
| `required` | 每条必需输入的明细，子字段见下表 | 指数、IM2611和持仓7400期权 |
| `configured_options` | 当前策略配置的期权合约总数，即 `len(strategy.contracts)` | 103，不是持仓数，也不是本次可开仓数 |
| `option_bars` | 本帧中存在观测的已配置期权键数量 | 86个期权有本分钟输入 |
| `future_bars` | 本帧中存在观测的已配置期货键数量 | 4个期货合约，不是4手持仓 |
| `index_present` | 指数键是否存在于本帧 | `true`，指数已进入本帧 |
| `synchronous_option_groups` | 每个配置期权分别检查“该期权＋绑定同月期货＋指数”是否都存在于本帧，满足的期权个数 | 86组行情齐全；组之间可以共用同一期货和指数 |
| `late_bars_total` | 当前分钟缓冲累计拒绝的迟到输入行数 | 332行，详情见第6节 |
| `ignored_stale_candidates_total` | 当前runner累计忽略的、非必需候选过期Bar行数 | 124行，详情见第6节 |

`required` 是动态集合：实际归属仓位非零、有本策略在途量、或目标非零的交易合约；再加指数，以及这些必需期权所绑定的同月期货。因此7400期权已有仓位时，即使期货仓位为0，IM2611也会因估值/对冲计算需要进入必需集合。

**`COMPLETE`不表示103个候选全链齐全。** 本例103−86＝17个配置期权未进入本帧，但必需腿齐全，所以仍是 `COMPLETE`。也不能从这17个直接推算“有17个合约故障”：可能是没有新更新、没有生成Bar、迟到或过期被排除；须看逐合约证据。

`synchronous_option_groups=86`不等于86个通过选约条件的候选，更不等于86个下单标的。上市期限、行权价、剩余交易日、时间价值、IV反解、最近到期组筛选和配仓仍在策略内部继续判断。

### 3.2 `required.<行情键>` 子字段

| 字段 | 含义 | 注意事项 |
| --- | --- | --- |
| `same_minute` | 该键是否存在于当前归一化分钟帧 | `true`才表示有本帧输入；不是只看缓存是否有旧价 |
| `price` | 当前帧该键的真实Bar收盘价，字符串 | 缺失时为 `null` |
| `source` | 绑定的逻辑来源，如 `market-bars`、`index-bars` | 是策略来源角色，不直接表示物理表名 |
| `bar_time` | 该观测保存的源事件时间 `source_ns` | 源为start标签时可与归一化 `minute`相差一分钟；DFS投影后也可能已是收盘边界 |
| `received_at` | runner接纳/处理该输入时记录的本机接收时间 | 指数DFS包含查询、缓存及投影路径；不是交易所发包时间，也不是首次落库时间 |
| `receive_delay_seconds` | `(received_ns - frame.valuation_ns) / 1e9`，保留3位小数 | 相对归一化业务分钟的到达间隔；包含生成、保存/查询、传输和处理等因素，不能直接当纯网络延迟 |
| `last_seen_minute` | runner最近记录该键的归一化业务分钟 | 全局最近观测，可能与本帧不同；不能代替 `same_minute`，也不保证就是策略当前缓存 |

样例中的三条必需输入：

| 行情键 | 角色 | 收盘价 | 接收时间 | 相对11:19边界的间隔 |
| --- | --- | --- | --- | --- |
| `000852` | 中证1000指数，自定义行情特征 | 6730.6706 | 11:19:14.205995 | 14.206秒 |
| `IM2611` | 持仓期权的同月期货 | 6668.4 | 11:19:00.549453 | 0.549秒 |
| `MO2611-C-7400` | 本策略持仓期权 | 46 | 11:19:01.759646 | 1.760秒 |

本帧宽限期为20秒。由 `deadline`反推第一条接纳时间为11:19:00.549111；它不必是 `required`表中的第一条，其他候选也能首先创建帧。指数在截止前约6.343秒到达。封帧比截止晚约0.211秒，是本次控制线程实际执行封帧的时间差，不能据此断言发生0.211秒网络延迟。

当前缓冲即使必需腿提前齐全，也会等到期限再封帧，以保留其他候选的接收机会。控制线程稍晚封帧不会延长接收期限；截止后到达的数据仍可能被拒绝。

## 4. 分钟决策汇总

### 4.1 身份、仓位、目标与价格

| 字段 | 含义 | 本次样例解释 |
| --- | --- | --- |
| `strategy_id` | 归属策略身份 | `option-vega-live` |
| `minute` | 本次决策的业务估值分钟 | 11:19 |
| `request_at` | 帧的 `request_ns`，本次决策使用的请求墙钟；等于行情摘要的 `sealed_at` | 11:19:20.760277；不是柜台订单受理或成交时间 |
| `status` | 本帧策略处理结果，见第4.4节 | `NO_TARGET_CHANGE` |
| `positions` | 进入本帧判断时读取的本策略归属净仓，仅打印非零项 | 7400期权 `-1`，空1手；不是整个物理账户的总仓 |
| `working` | 本策略归属的有符号在途数量，仅打印非零项 | `{}`，本次读取没有非零在途量；不是全账户活动订单查询 |
| `option_goals` | 策略当前期权目标手数；打印目标非零或决策起点有持仓的键 | 7400目标仍为 `-1`；是目标总仓，不是再卖1手 |
| `future_goals` | 策略当前期货目标手数，显示筛选规则同上 | `{}`，没有需要显示的非零目标或已有期货仓位项；不表示代码没配置期货 |
| `price_cache` | 与仓位、在途、目标及所需同月期货/指数有关的策略最新价格缓存 | 不是103个期权全部报价快照 |
| `target_submissions_total` | 策略成功调用目标接口后的累计提交次数；可从信号检查点恢复 | 1；本帧没有新增，不等于本次下了1笔单 |
| `fills_received_total` | 当前策略实例收到的 `on_fill` 回调次数 | 0，不能据此否定恢复出来的历史仓位 |
| `order_updates_received_total` | 当前策略实例收到的 `on_order_update` 回调次数 | 0，不代表柜台从未有过订单 |

`working`是有符号归属数量，不是订单条数。不要把空字典直接等同于全账户没有活动单；抵消后的净量也不能替代OMS订单明细。数量字符串 `"0"`如果出现于目标，可能表示需要将既有持仓降至零；零项并非总被打印。

`price_cache.<行情键>`包含：

| 字段 | 含义 |
| --- | --- |
| `price` | 策略缓存中的收盘价格，浮点数 |
| `minute` | 该缓存价格对应的归一化业务分钟 |
| `age_seconds` | `(当前帧估值分钟 - 缓存业务分钟) / 1e9`，不是墙钟减接收时间 |

本例三个 `age_seconds=0.0`表示缓存都属于11:19业务分钟。决策实际在11:19:20.760执行，所以它们不是“刚刚零延迟收到”；指数仍是在边界后14.206秒才到达。持仓管理使用原有新鲜度政策；开新仓额外要求期权、同月期货、指数三腿同分钟。

### 4.2 选约字段 `entry` / `entry_slot`

`entry_slot`来自 `config.option_slot`。比较的是 `minute`对应的北京时间HH:MM，而非 `request_at`的秒数。本例配置13:36，11:19未到，因此 `WAIT_SLOT`。这是当前会话参数，不能用代码默认选约时点替代。

| `entry` 值 | 具体含义 |
| --- | --- |
| `WAIT_SLOT` | 当前业务分钟早于选约时点 |
| `DUE` | 到达选约时点且当日尚未标记选约；是初始分支标记，正常执行后通常被具体结果替换 |
| `SLOT_PASSED` | 已超过选约时点，且当日未标记选约；当前实现不会在之后任意分钟自动补选 |
| `ALREADY_SELECTED` | 当日在 `sent_days`中，已执行并标记选约尝试；不保证该次选出了合约或产生了成交 |
| `WORKING_ORDERS` | 到选约时点但仍有期权在途量，该次选约分支未继续配仓 |
| `NO_VALID_ENTRY` | 已筛选，但无有效候选，并标记当日选约尝试完成 |
| `ZERO_ALLOCATION` | 有候选，但配仓结果为空，未形成非零开仓目标 |
| `TARGET` | 配仓得到了目标；后续仍须由执行层落实，不能当作成交 |

当本帧执行选约尝试时，可能附加 `entry_audit`：`signal_ns`为业务估值时间纳秒，`request_ns`为请求时间纳秒，`date`和`slot`为业务日期/时点，`outcome`为上述具体结果，`candidate_count`为通过初步条件的候选数（在最近到期组再次筛选之前），`targets`为配仓结果；存在目标时还可能有 `future_bindings`，记录期权到同月期货的绑定。`candidate_count`与行情汇总的同分钟组数不是同一个指标。

### 4.3 退出检查 `exit_checks` 与对冲 `hedge`

`exit_checks`逐条记录需要管理的期权（实际仓位、目标或在途量非零）在没有该期权在途量时的常规退出检查。有在途量、恢复等待或末日清仓提前分支时，列表可能为空；空列表不能直接解释为没有持仓。

| 子字段 | 含义 | 本次值 |
| --- | --- | --- |
| `key` | 检查的期权合约 | MO2611-C-7400 |
| `price` | 用于检查的期权收盘价 | 46.0 |
| `index` | 用于计算认购内在价值的指数价格 | 6730.6706 |
| `remaining_days` | 剩余交易日：不含估值当日，包含最后交易日；日历不完整时可能只是已知下界 | 26 |
| `remaining_days_exact` | 最后交易日是否落在已知日历覆盖末端之内；为true时按当前日历精确计数 | true |
| `close_remaining_days` | 剩余交易日常规平仓阈值，来自策略配置 | 2 |
| `time_value` | `期权价 - max(指数价 - 行权价, 0)`；单位为报价点数，不乘合约乘数 | 46.0 |
| `should_close` | `remaining_days <= close_remaining_days`或`time_value <= 0` | false |

本例6730.6706低于行权价7400，认购内在价值为0，所以时间价值46−0＝46。26大于2且46大于0，常规退出条件不成立。这里的退出时间价值使用指数；IV/Delta反解使用同月期货价格，两者不能混为一个输入。`min_time_value`用于候选/Greeks计算的门槛，不是本处退出阈值。

`should_close=true`是策略判断，不等于已平仓；后续还要看目标提交、执行及成交。指定 `final_day`后的末日清仓另走优先分支，不依赖此列表逐项变成true。

| `hedge` 值 | 含义 |
| --- | --- |
| `NOT_EVALUATED` | 初始标记；恢复等待、提前清仓分支或异常时可能尚未执行常规对冲分支 |
| `NOT_DUE` | 本帧没有触发重算对冲 |
| `WAIT_WORKING_ORDERS` | 已触发重算，但配置期货中存在本策略非零在途量，暂不重算 |
| `EVALUATED` | 进入了对冲计算分支；可能仍得出与原目标相同的手数，无需提交 |

`hedge_reasons`可同时含以下值：

| 原因 | 代码条件 |
| --- | --- |
| `TARGET_CHANGED` | 前面的常规退出或选约流程设置了目标变化标记 |
| `POSITION_CHANGED` | 当前期权归属仓位快照与上次对冲计算记录的期权仓位快照不同；初次尚无对照快照也会触发 |
| `CONFIGURED_SLOT` | 当前业务HH:MM在 `config.hedge_slots`中 |

对冲以实际已成交期权仓位计算Delta暴露，而不是将尚未成交的期权目标当作实际暴露；各同月期货目标为 `round(-期权Delta暴露 / 期货合约乘数)`，再检查最大手数。因整数手取整，即使有期权空仓，也可能得出期货0手。本例是 `NOT_DUE`、原因列表为空：只能说11:19没有重算，不能从该条日志推断当时的具体Delta值或为何过去计算为零。

### 4.4 决策 `status` 及附加字段

| 状态 | 含义与后续判断 |
| --- | --- |
| `EVALUATING` | 策略进入本帧时的初始状态，通常会被结果状态覆盖 |
| `NO_TARGET_CHANGE` | 已走完本次正常判断，没有在本帧提交新目标；不表示没执行判断 |
| `TARGET_SUBMITTED` | 已调用目标接口；不等同于柜台受理、订单笔数或成交 |
| `RESUME_WAIT` | 恢复/断档后部分必需腿尚未更新到恢复基准之后，暂时返回；附带 `missing`键列表 |
| `FINAL_FLAT_CHECK` | 进入配置的最后清仓日及时点检查，但该帧没有新的目标提交；可能在等在途单或已经零仓 |
| `SKIPPED_INDEX` | runner封帧后发现DFS指数本分钟缺失，跳过整次策略处理；附带 `missing` |
| `ERROR` | 策略处理抛出异常，附带 `failure`，保留停机/关闭接收门的错误行为 |

`TARGET_SUBMITTED`时可能出现 `action`（`REBALANCE`或`FINAL_FLAT`）和 `targets`（带交易所后缀的路由目标）。目标表示期望总持仓，不是买卖增量；完整内部提交包含零目标，但日志展示会过滤部分无仓位的零项。

各分支字段不保证完全相同。例如 `SKIPPED_INDEX`是runner直接输出的简化记录，通常只有身份、业务分钟、状态和缺失列表，没有仓位、价格缓存或提交计数。`ERROR`是在已有决策上下文上补充错误信息，不保证前面各项检查已经完成。

## 5. 分钟运行心跳

| 字段 | 含义 | 本次样例解释 |
| --- | --- | --- |
| `strategy_id` | 当前策略身份 | option-vega-live |
| `wall_time` | 本次控制线程轮询的墙钟 | 11:20:00.182880 |
| `last_closed_minute` | 分钟缓冲最近封闭的业务分钟；尚未封帧时为null | 11:19；是封帧位置，不自动保证该帧成功决策或成交 |
| `pending_minutes` | 当前缓冲中已创建、尚未封闭的分钟，排序后列出 | `[]`；此刻没有待封帧，不代表将来的11:20行情不会到达 |
| `strategy_frames` | 当前策略实例进入 `_frame()`的累计次数 | 87；含恢复等待或进入后报错的帧，缺指数在runner跳过的帧不计入 |
| `last_decision_status` | 策略对象最近 `last_decision.status` | NO_TARGET_CHANGE；不是“刚刚11:20又判断了一次” |
| `failure` | runner已记录的失败原因，尚无记录为null | null；只说明该时刻没有runner失败记录 |

心跳在该次 `flush_frames()`之前输出，但在 `poll_features()`之后；不能据此推断整个该轮后续检查都已经完成。如果runner刚跳过了缺指数帧，策略对象的 `last_decision`并不会同步更新为 `SKIPPED_INDEX`，心跳可能仍显示上一次实际进入策略的状态。诊断时应同时看最近的分钟决策汇总。

## 6. 累计计数与恢复边界

| 字段 | 计数对象/重置范围 | 是否从当前08信号检查点恢复 |
| --- | --- | --- |
| `late_bars_total` | 当前 `MinuteFrameBuffer.late_count`；新缓冲重置，`begin_bars()`也重建缓冲 | 否 |
| `ignored_stale_candidates_total` | 当前runner忽略过期非必需候选的行数 | 否 |
| `strategy_frames` | 当前策略实例进入 `_frame()`次数 | 否 |
| `target_submissions_total` | 策略目标接口提交次数 | 是，来自 `OptionVegaCheckpoint.submissions` |
| `fills_received_total` | 当前策略实例成交事件回调数，不是手数、柜台累计成交笔数或全部历史成交数 | 否；恢复期间若另外分发事件，按实际回调增加 |
| `order_updates_received_total` | 当前策略实例订单状态事件回调数，不是订单条数；同一订单可有多个回报 | 否；按实际回调增加 |

新建进程或重新装配交易窗口可能创建新runner/策略，不能直接把窗口前后两个累计值相减计算业务变化，先确认实例及恢复边界。目标提交次数可跨恢复延续，其他数不一定延续。

`late_bars_total`在两种情况下增加：

1. 输入的业务分钟已被缓冲封闭（`valuation_ns <= last_closed_ns`）。
2. 对应分钟仍待封，但输入接收时间已经超过其最初截止时间。

同一分钟同键、同价格的重复输入会被忽略，但不因此增加迟到数；内容冲突会报错。计数不是去重后的合约数，也不直接说明持仓腿迟到。

`ignored_stale_candidates_total`在进入分钟缓冲之前增加：实时Bar的业务年龄超过该来源允许上限，并且该合约不是当时的必需腿，程序警告后忽略。必需腿过期或未来时间输入会走错误处理。相同输入若已在此忽略，不会再进入缓冲增加迟到数；另一些尚未超过年龄上限、但错过帧期限的Bar可以增加迟到数。

因此不能把332与124简单相加当成“456个缺失合约”，也不能认为它们全部发生在11:19。应观察连续日志的增量，再结合具体键、分钟及原始tick判断。低活跃合约等待下一条tick才输出旧Bar的行为，可能造成这些计数增长，但计数本身不能定位根因。
